YakuAI · documento técnico

Arquitectura del software

YakuAI es una aplicación web con frontend React, API REST Laravel y persistencia relacional. El backend concentra la autorización, el acceso a datos y las reglas de negocio.

Arquitectura general

Vista de alto nivel de los componentes principales.

Aplicación web + API

  1. Usuarios

    Personal técnico y agricultores acceden desde el navegador.

  2. Frontend

    React presenta pantallas y recoge las acciones de usuario.

  3. API REST

    Laravel recibe solicitudes JSON bajo /api/v1.

  4. Dominio y datos

    Servicios y modelos aplican reglas y acceden a MySQL.

  5. Respuesta

    La API devuelve datos o errores para actualizar la interfaz.

Tecnologías utilizadas

Stack principal implementado en el proyecto.

Frontend

Interfaz, navegación y experiencia de usuario.

  • React 19 y TypeScript
  • Vite y React Router
  • Tailwind CSS y componentes compartidos
  • Fetch API para solicitudes HTTP
  • Leaflet y Recharts para mapas y gráficos

Backend

API, autenticación, permisos y lógica de negocio.

  • PHP 8.3 y Laravel 13
  • Laravel Sanctum para autenticación por token
  • API JSON bajo /api/v1
  • Controladores, modelos Eloquent y servicios
  • Migraciones y seeders

Datos e infraestructura

Persistencia y ejecución de los servicios.

  • MySQL 8.4
  • Redis para caché y colas
  • Docker Compose
  • Nginx y PHP-FPM
  • OpenWeatherMap, SMTP y WhatsApp opcional

Backend · MVC con servicios

Laravel monolítico organizado por responsabilidades.

Rutas

Definen endpoints y conectan solicitudes con controladores.

Controladores

Validan datos, coordinan el caso de uso y preparan respuestas.

Servicios

Concentran reglas de dominio e integraciones.

Modelos Eloquent

Representan entidades y consultan o guardan datos en MySQL.

Ejemplos: HydroService calcula evaluaciones de riego; OwmService integra datos meteorológicos; SensorNormalizer normaliza las lecturas.

Frontend · módulos y componentes

Organización modular por pantallas y funcionalidades.

Aplicación y sesión

app/ gestiona rutas, autenticación y navegación por rol.

Páginas

pages/ compone las pantallas de la aplicación.

Funcionalidades

features/ agrupa lógica y utilidades por dominio.

UI y API

components/, hooks/ y api/ comparten interfaz y acceso al backend.

Enfoque: el backend sigue MVC con servicios. El frontend usa una organización modular por funcionalidad y componentes reutilizables; no aplica MVC tradicional.
